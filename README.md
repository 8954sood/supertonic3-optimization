# supertonic3-optimization

[Supertonic 3](https://huggingface.co/Supertone/supertonic-3)를 **CPU 한 스레드·실제 denoising 8회**로 실행하기 위한 최적화 프로젝트입니다. 현재 기준 모델은 **F1200**, Linux x86 AVX2의 최신 엔진은 **v5**입니다. 기존 v4도 대조용으로 보존합니다. Mac ARM64에서는 조건 캐시와 행 병렬 정규화를 선택할 수 있습니다.

[모델 다운로드](https://huggingface.co/babihoba/supertonic3-optimization) · [학습 데이터](https://huggingface.co/datasets/babihoba/supertonic3-optimization-data) · [재현 안내](docs/REPRODUCING.md) · [전체 실험 기록](WORK_LOG.md)

## 현재 성능 — 동일 조건 재측정

> **측정 환경 주의:** 이 서버는 1코어·약 1GB RAM의 매우 낮은 사양이며, 다른 프로세스도 함께 실행 중입니다. 가용 CPU·메모리와 공유 부하의 영향으로 반복 측정값과 버전 간 성능 비교의 일관성이 낮습니다. 아래 RTF는 해당 환경에서 관측한 값이며, 안정적인 성능 보장이나 작은 차이의 확정적인 순위로 해석하지 마세요. 여유 있는 전용 환경에서 별도 재검증이 필요합니다.

**Oracle x86 AMD EPYC 7551 · 물리 1코어 · RAM 약 1GB**에서 논리 CPU 하나에 고정하고 추론 스레드를 1로 제한했습니다. **F1200 가중치·양자화·실제 denoising 8회·M1 음색·KO/EN 짧은 문장·현재 Python 런타임**을 통일했습니다. 아래 값은 각 조건의 **새 프로세스 6회 측정 중앙값**입니다. 매번 예열한 뒤 측정하며 모델 로딩·파일 저장·해시는 시간에서 제외합니다.

| 엔진 | 한국어 1.00× | 영어 1.00× | 한국어 2.00× | 영어 2.00× |
| --- | ---: | ---: | ---: | ---: |
| v1 | 1.1437 | 1.3514 | 1.5730 | 1.5734 |
| v2 | 1.0514 | 1.0529 | 1.4160 | 1.3997 |
| v3 · 미채택 실험판 | 1.0081 | 1.0407 | 1.3873 | 1.3780 |
| v4 | 1.0230 | 1.0246 | 1.3606 | 1.3687 |
| v5 · 엔진만 교체 | 1.0150 | 1.0204 | 1.3569 | 1.4777 |
| v5 · 현재 패키지 | 1.0176 | 1.1797 | 1.4043 | 1.3678 |

**RTF = 생성 시간 ÷ 최종 음성 길이. 작을수록 빠르며 1 미만이면 실시간보다 빠릅니다.** 1.00×와 2.00×는 음성 길이와 내부 계산량이 다르므로 서로 다른 속도의 RTF로 엔진 순위를 매기지 않습니다. 2.00×는 기존 내부 생성 1.35× → 출력 2.00× 경로입니다.

v1/v2/v3/v4/v5 엔진만 교체한 행은 **같은 native 그래프**를 씁니다. 현재 v5 패키지 행만 기존 batch-one 그래프 준비까지 포함합니다. 과거 버전별 Python 스택을 복원한 비교는 아닙니다. v3는 이번 표에 포함했어도 미채택 실험판입니다.

총 **84개 새 프로세스·168개 측정 음성**을 순서를 균형 있게 바꾸어 비교했습니다. 느린 실행도 삭제하지 않았습니다. 최대 표본 프로세스 트리 RSS는 **391.6MB**, 최소 시스템 여유 메모리는 **115.4MB**였으며 모든 메모리 감시를 통과했습니다. 이 값은 이번 짧은 입력 범위의 관측값입니다.

**현재 v5 패키지가 모든 조건에서 더 빠르다는 결론은 내리지 않습니다.** 영어 1.00×의 RTF 중앙값은 v4 **1.0246**, 현재 v5 패키지 **1.1797**였고, 같은 블록의 시간 감소율 중앙값도 **−15.94%**로 느렸습니다. 지연이 다른 단계에서도 발생해 원인은 분리 검증이 필요합니다. 추가로 **같은 v5 엔진을 고정한 공유 frontend 10쌍 대조**에서는 batch-one의 쌍별 시간 감소율이 **−0.19%로 거의 같았고**, 큰 차이가 재현되지 않았습니다. 이 진단은 두 VE 세션이 상주하는 다른 조건이므로 위 새 프로세스 RTF 표를 대체하지 않습니다. [추가 진단 원본](results/round18_batch_diagnostic.json)

과거 v2의 1.05× RTF **0.948 / 0.957**은 당시 관측값으로 보존합니다. 이번 1.05× 재검사는 v2 **1.0515 / 1.0540**, 현재 v5 패키지 **1.0096 / 1.0147**입니다. 과거의 낮은 수치가 현재 공유 환경에서 지속적으로 재현되지는 않았습니다.

## 버전별 최적화와 개선율

모델 절의 **RTF 감소율**은 `(1 − 개선 후 RTF / 비교 기준 RTF) × 100`입니다. 엔진 절은 각 블록에서 계산한 **쌍별 생성 시간 감소율의 중앙값**이며, RTF 중앙값끼리 나눈 값과 다를 수 있습니다. 양수는 빨라짐, 음수는 느려짐입니다.

### 1. 모델 최적화

같은 EPYC 서버·같은 짧은 KO/EN 문장·실제 8회 생성의 역사적 결과입니다. 모델이 달라 출력 길이도 달라지며, 서로 다른 측정 배치의 관측값입니다.

| 단계 | 한국어 RTF | 영어 RTF | RTF 감소율: KO / EN | 바꾼 내용 |
| --- | ---: | ---: | --- | --- |
| [전체 INT8 기준](results/epyc_full_int8_8.json) | 2.220 | 2.198 | 기준 | 원래 CFG4 계산을 유지한 양자화 모델 |
| [혼합 폭 학생](results/epyc_mixed_selected_v1_8.json) | 1.879 | 1.844 | **15.4% / 16.1%** · 전체 INT8 대비 | 층별 FFN 폭을 달리 줄이고 교사 출력으로 학습, CFG4 유지 |
| [B: CFG 증류](results/epyc_cfg_selected_v1_8.json) | 1.095 | 1.106 | **41.7% / 40.0%** · 혼합 폭 대비 | CFG4의 조건·무조건 분기 결합을 단일 조건 경로가 학습 |
| [E400](results/round6_paired_E_F.json) | 1.056 | 1.069 | 속도 개선 목적의 비교 아님 | 원본 FP32·CFG4·50스텝 교사로 8스텝 학생 재학습, 400회 |
| [F1200 · 현재 기준](results/round6_paired_E_F.json) | 1.052 | 1.070 | E400 대비 **일관된 속도 개선 확인 못함** | 같은 원본 교사로 1,200회 학습, 청취 후 기준 모델로 선택 |

B까지의 관측 RTF는 전체 INT8 기준보다 KO **50.7%**, EN **49.7%** 낮았습니다. 전체 INT8 기준도 이미 최적화된 모델입니다. 원본 FP32는 1GB 서버의 메모리 감시에서 중단됐으므로 **원본 대비 서버 가속률은 제시하지 않습니다**.

폭 1024 후보는 B 대비 RTF가 약 **19.2% / 19.5%** 더 낮았지만 발음 오류와 청취 품질 저하로 채택하지 않았습니다. 현재는 F1200의 크기와 가중치를 고정하고 엔진을 개선합니다. [모델·품질 실험 기록](records/2026-10-29/ROUND5_LOCAL.md)

### 2. 엔진 최적화 — 동일 조건의 쌍별 시간 비교

아래는 위 RTF 표와 **같은 18차 실행**에서 계산했습니다. 각 행에 적힌 비교 기준과 같은 블록끼리 비교하며, 각 속도는 별도로 봅니다. 서로 다른 행의 감소율을 더해 누적 가속률로 계산하지 않습니다.

| 버전 | 비교 기준 | 1.00× 감소율 KO / EN | 2.00× 감소율 KO / EN | 방법 |
| --- | --- | ---: | ---: | --- |
| v1 | 기준 | 기준 | 기준 | 정확한 K4 AVX2 정수 곱, 가중치 packing 재사용 |
| v2 | v1 | +7.93% / +22.15% | +9.34% / +10.09% | 안전한 K8 부분합의 정수 확장 공유, 정확한 S32 fallback |
| v3 · 미채택 실험판 | v2 | +3.55% / +1.89% | +2.17% / +0.88% | K16 부분합 후보. 미채택 실험판 |
| v4 | v2 | +3.12% / +3.54% | +3.18% / +1.83% | 4행 × 16열 타일, 활성값 읽기 재사용 |
| v5 · 엔진만 교체 | v4 | +0.82% / +0.23% | +0.20% / -8.24% | 희소 unsafe 항의 정확한 분리·복구, safe-K8 잔여 행 처리 |
| v5 · 현재 패키지 | v5 엔진만 | +0.33% / -14.42% | -2.04% / +7.01% | batch-one 크기 고정, 고정 key 계산을 로딩 때 처리 |

소수 퍼센트 차이는 이 환경에서 안정적인 개선으로 확정하지 않습니다. **RTF 중앙값 비교와 쌍별 감소율은 다른 통계**입니다. 예를 들어 현재 v5 패키지의 영어 정배속은 v2보다 RTF 중앙값이 높지만, v2 대비 쌍별 감소율 중앙값은 +2.67%입니다. 큰 지연이 서로 다른 실행에 섞여 요약 방식에 따라 방향도 달라지므로 작은 차이의 순위를 단정하지 않습니다.

엔진 변경은 학습 가중치·양자화·8회 계산을 유지하며, 이번 **168개 측정 파형은 같은 속도·문장끼리 float32 바이트까지 모두 같았습니다.** v3를 새로 빌드한 뒤 정수 경계·tail·cache 17개 검사도 통과했습니다. 새 WER/CER/MOS 평가를 한 것은 아닙니다. 과거 실험과 판단은 원본 기록에 보존합니다. ### 3. 표준 ORT 조건 캐시 — M4 Max 스트리밍 측정

F1200·내부 배속 패키지의 문장 조건 194개 연산을 8스텝마다 반복하던 경로에서 분리했습니다. Mac CPU 한 스레드의 교대 비교에서 짧은 KO/EN·M1/F1·1.0/1.5/2.0× **12조합의 생성 시간 감소율 중앙값은 약 4.0%**, 실제 HTTP 스트리밍 8조합의 **전체 응답 시간 감소율 중앙값은 3.5%**였습니다. **남성 한국어 1.0×는 사실상 개선이 없었으며**, 나머지 스트리밍 7조합은 약 1.1~6.0% 줄었습니다.

가중치·양자화·8스텝을 유지했고, 짧은 문장과 장문·소수점 배속에서 float32 파형이 같았습니다. Linux v4/v5에는 이미 조건 캐시가 있어 이 변환을 추가 적용하지 않습니다. 이 수치는 Oracle ARM 서버 결과가 아닙니다. [준비 명령](docs/SERVER.md#표준-ort-조건-캐시-선택) · [12차 측정·검증 범위](records/2026-10-30/ROUND12_ENGINE.md)

### 4. 행 병렬 정규화 — M4 Max, 실제 8스텝 유지

정규화의 한 행 안에서 계산 순서를 유지하면서 **독립된 4개 행을 NEON으로 함께 처리**했습니다. 벡터 추정기의 FP32 정규화 36곳을 바꾸며 가중치·양자화·배속 방식은 유지합니다. 설치된 ORT와 작은 연산의 결과가 일치하는지 시작할 때 검사하고, 다르면 실행을 거부합니다.

14차에서는 **16행을 함께 처리하고 남은 구간을 8→4행으로 처리**하도록 개선했습니다. 32행 후보는 16행보다 일관되게 빠르지 않아 선택하지 않았습니다. 기본 빌드는 16행입니다. **15차에서는 duration 처리기 10곳·텍스트 처리기 15곳·보코더 10곳에도 확장해 총 71곳에 적용**했습니다. 그래프의 크기 정보를 보존해 기존 행렬곱·GELU 융합 경로가 유지되도록 했습니다. 새 사용자는 `prepare_row_norm.py --all-parts`로 준비하며, 기존 사용자의 추가 변환 방법은 아래 실행 안내에 있습니다.

| 비교 | 생성 시간 감소율 중앙값 | 실제 HTTP 전체 시간 감소율 중앙값 |
| --- | ---: | ---: |
| 12차 조건 캐시 → 행 병렬 정규화 | **8.24%** · 12조합 × 6쌍 | **9.04%** · 8조합 × 6쌍 |
| 13차 4행 → 14차 16행·계층적 잔여 처리 | **3.30%** · 12조합 × 6쌍 | **3.82%** · 8조합 × 6쌍 |
| 14차 벡터 추정기만 → 15차 전체 정규화 | **4.73%** · 12조합 × 6쌍 | **4.47%** · 8조합 × 6쌍 |
| 공개 retime 표준 패키지 → 15차 엔진 | **19.32%** · 8조합 × 6쌍 | 별도 측정 안 함 |

각 조합의 쌍별 감소율 중앙값을 같은 비중으로 집계했습니다. 누적 개선율도 별도로 교대 측정했으며 이전 퍼센트를 더하지 않았습니다. 15차의 HTTP 8조합은 PCM이 같고, 별도 파형 바이트 96쌍도 일치했습니다. 15차의 첫 오디오 도착 시간 감소율 중앙값은 **4.77%**였습니다. **Mac 실측이며 Oracle ARM 성능은 아직 검증하지 않았습니다.** 이 선택 경로는 ARM64 네이티브 빌드가 필요합니다. [실행 방법](docs/SERVER.md#arm64-행-병렬-정규화-선택) · [13차 기록](records/2026-10-30/ROUND13_ENGINE.md) · [14차 기록](records/2026-10-30/ROUND14_ENGINE.md) · [15차 기록](records/2026-10-30/ROUND15_ENGINE.md)

### 5. 초기 FP32 그래프 최적화 — M4 Max 별도 측정

1×1 Conv를 행렬곱으로 바꾸고, 매 스텝 반복되던 문장 조건을 한 번만 계산했습니다. 원래 CFG4·FP32·8스텝을 유지한 CPU 한 스레드 비교에서 한국어 RTF **0.305 → 0.067**, 영어 **0.317 → 0.069**, 각각 **78.0% / 78.1% 감소**했습니다. 짧고 긴 4문장의 가속비는 4.54~4.71배였습니다. 이 결과를 EPYC·Oracle ARM 성능으로 환산하지 않습니다. [측정 원본](results/paired_fp32_cached_8.json)

## Oracle ARM 측정

사용자가 별도로 측정한 **Neoverse-N1 · 2코어 · 12GB**의 결과입니다. 대상은 **이전 B 모델**이며, F1200·엔진 v4·내부 2배속 후보의 결과와 구분합니다.

| 실행 설정 | 짧고 긴 KO/EN 4문장 RTF 범위 |
| --- | ---: |
| 한 스레드 | **0.276~0.283** |
| 두 스레드 | **0.153~0.161** |

각 문장 워밍업 후 5회 중앙값이며, 두 설정의 저장 음성 4쌍은 PCM16 샘플이 같았습니다. 기본 실행 설정은 한 스레드입니다. v4/v5 native 커널은 Linux x86_64 AVX2용이며 ARM은 표준 ORT 경로를 사용합니다. [ARM 측정 PR #1](https://github.com/8954sood/supertonic3-optimization/pull/1)

## 빠른 시작

Python 3.12 이상을 사용합니다. Git에는 소스와 기록을, Hugging Face에는 모델·체크포인트·데이터를 보관합니다. 기본 F1200 패키지는 약 **194MB**이며 공개 다운로드에 토큰이 필요하지 않습니다.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python download_artifacts.py --purpose inference
python synthesize.py '안녕하세요. 하나의 스레드로 음성을 만듭니다.' \
  --model .hf-assets/model/models/round5-original50-student \
  --lang ko --steps 8 --speed 1.0 --output samples/hello.wav
```

위 명령은 이식 가능한 표준 ORT 패키지를 실행합니다. **v5 커널 빌드·그래프 변환·제한 서버 측정은 [EPYC 엔진 설정](docs/REPRODUCING.md#epyc용-엔진-실험)**을 따라 별도로 준비하세요. 변환과 학습은 RAM이 넉넉한 개발 환경에서 수행합니다.

### 내부 2배속 후보 사용

```bash
python download_artifacts.py --purpose inference --model round8-latent-retime-g135
python synthesize.py '안녕하세요. 오래된 컴퓨터에서도 빠르게 음성을 생성합니다.' \
  --model .hf-assets/model/models/round8-latent-retime-g135 \
  --lang ko --voice M1 --steps 8 --speed 2.0 --output samples/fast.wav
```

F1200 가중치와 8회를 유지하며 **추가 학습·추가 파라미터·파형 생성 후 배속 필터 없이** 보코더 그래프 안에서 처리합니다. 2.0×에만 새 경로를 적용하고 다른 속도는 기존 경로를 사용합니다.

기본 duration 방식의 2배속에서 확인한 누락·뭉개짐을 줄였고, 짧은 남성 샘플은 사용자 청취에서 개선됐습니다. 다만 확대 개발 검증 16개에서 **한국어 CER 51/193(26.42%), 영어 WER 1/96(1.04%)**이 남습니다. 모든 문장의 누락 해결이나 원본 음질 동등성을 보장하지 않으며, ASR 오류율은 지각 음질 점수가 아닙니다. [배속 품질·실패 시도·검증 범위](records/2026-10-29/ROUND8_NATIVE_SPEED.md)

## 서버·스트리밍

원본 형식의 `/v1/tts`, `/v1/audio/speech`, 배치·음색 API와 **문장 묶음 단위 PCM·SSE 스트리밍**을 제공합니다. 모델을 한 번 로드해 재사용하며 묶음마다 8스텝을 유지합니다.

```bash
python -m pip install -r requirements-serve.txt
python serve.py --model .hf-assets/model/models/round5-original50-student
```

브라우저에서 <http://127.0.0.1:7788/>로 접속하면 생성 중인 음성을 바로 들을 수 있습니다. 2배속 후보는 `--model`에 다운로드한 `round8-latent-retime-g135` 경로를 지정합니다. [서버 API·스트리밍 형식·첫 오디오 지연·측정 안내](docs/SERVER.md)
