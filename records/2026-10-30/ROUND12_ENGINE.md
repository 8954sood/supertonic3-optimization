# 12차: 표준 ORT 조건 캐시와 스트리밍 성능

## 출발점과 채택 범위

사용자는 최신 코드를 받은 뒤 성능 최적화를 계속하도록 요청했다. main `877ea6e`에서 로컬 변경 없이 시작했고, `git pull --ff-only origin main`은 이미 최신이라고 반환했다. 별도 브랜치를 만들지 않았다.

F1200의 가중치·양자화·실제 denoising 8회·추론 한 스레드를 고정했다. 이번 채택 대상은 **표준 ORT retime 패키지의 문장 조건 캐시**다. 기법 자체는 초기 실험과 Linux v4에서도 사용했다. 현재 공개 retime 표준 패키지에는 캐시가 없으므로 이 경로를 따로 변환·검증했다. Linux AVX2 v4를 다시 최적화했다고 주장하지 않는다.

## 변경 방법

`prepare_condition_cache.py`는 기존 `experiments.optimize.split`을 이용해 스텝마다 변하지 않는 조건 계산을 분리한다. `noisy_latent`와 `current_step`에 의존하는 노드는 반복 경로에 남는다. 결과는 문장 묶음당 한 번 실행하는 `condition.onnx`와 8회 실행하는 `vector_estimator.onnx`다. 기존 runtime과 서버는 이 구성을 이미 지원하므로 추론 코드·API·문장 분할·배속 설정을 바꾸지 않았다.

- 반복 경로 노드: 1,510 → 1,316. 조건 계산 194개, 경계 텐서 19개.
- 원본 initializer 628개를 두 그래프의 합집합과 직렬화 바이트까지 비교했다. 변경·누락 없이 일치했다.
- 원본 vector SHA-256: `7c81ab7f0ddcc4266743701599a8708d2edd1be04285770f996e84a8bb5f4447`.
- 가중치와 보코더의 2.0× 전용 1.35→2.0 retime 동작은 그대로다. 후처리·새 학습·새 양자화가 없다.
- 준비 도구는 임시 폴더에서 검증한 뒤 완성 폴더를 공개한다. 실패하면 임시 파일을 지운다. 기존 출력·중첩 경로·이미 캐시된 입력을 거부한다.
- 기본은 파일 복사다. 이번 로컬 후보는 `--link-assets`로 변경하지 않는 파일을 공유해 중복 용량을 줄였다. 변환할 파일과 manifest는 링크를 끊고 기록하며 원본을 보존했다. 링크한 두 패키지는 읽기 전용으로 취급한다.

최종 준비 도구로 다시 생성한 그래프가 측정했던 후보 그래프와 바이트까지 같음을 확인했다. 검증용 임시 패키지는 제거했다. [빌드 영수증](../../results/round12_cache_build.json)

## 교대 성능 측정

M4 Max의 CPUExecutionProvider에서 ORT intra/inter thread를 각각 1로 제한했다. 추론은 순차 실행했다. 워밍업·모델 로딩·프로파일링을 시간 비교에서 제외했다. 두 엔진을 같은 프로세스에 상주시켜 같은 문장·음색·배속·seed를 비교했고, 쌍마다 실행 순서를 바꿨다. 이는 Mac 관측값이며 ARM/EPYC의 속도나 메모리로 환산할 수 없다. 두 엔진을 함께 로드한 RSS는 단일 운영 엔진 메모리로 제시하지 않는다.

먼저 짧은 KO/EN × M1/F1 × 1.0/1.5/2.0×의 12조합을 각각 5쌍 실행했다. 모든 실행의 float32 파형이 일치했고, **조합별 쌍별 생성 시간 감소율 중앙값들의 중앙값은 4.01%**였다. M1 KO 1.0×는 0.21%로 사실상 차이가 없었다. [원시 생성 비교](../../results/round12_paired_portable_cache.json)

별도 HTTP 검사는 실제 임시 Uvicorn 서버 두 개와 TCP 연결을 사용했다. 앞 검사와 반대로 후보 서버부터 초기화했고, 요청은 한 번에 하나씩 실행했다. KO/EN × M1/F1 × 1.0/2.0×의 8조합을 각각 3쌍 비교했다. 첫 오디오 수신·추론 합계·HTTP 완료 시간을 따로 기록했다. 워밍업을 포함한 각 결과의 PCM을 기준 출력과 대조했다.

| 조합 | 기준 생성 RTF 중앙값 | 캐시 생성 RTF 중앙값 | 쌍별 HTTP 전체 시간 감소율 중앙값 | 캐시 첫 오디오 중앙값 |
| --- | ---: | ---: | ---: | ---: |
| M1 KO 1.0× | 0.03301 | 0.03304 | -0.13% | 0.317초 |
| M1 KO 2.0× | 0.04777 | 0.04622 | 3.13% | 0.229초 |
| M1 EN 1.0× | 0.03419 | 0.03352 | 4.16% | 0.184초 |
| M1 EN 2.0× | 0.04784 | 0.04585 | 3.83% | 0.134초 |
| F1 KO 1.0× | 0.03431 | 0.03295 | 5.73% | 0.321초 |
| F1 KO 2.0× | 0.04746 | 0.04668 | 2.42% | 0.230초 |
| F1 EN 1.0× | 0.03383 | 0.03172 | 5.95% | 0.179초 |
| F1 EN 2.0× | 0.04715 | 0.04665 | 1.05% | 0.133초 |

8조합의 감소율 중앙값은 **추론 합계 3.66%, HTTP 전체 시간 3.48%, 첫 오디오 2.87%**였다. 이는 각 조합을 같은 비중으로 집계한 값이며 전체 작업량으로 가중한 처리량 개선율이 아니다. 감소율은 각 쌍의 `(1 − 후보 시간 / 기준 시간) × 100`으로 구하므로 표의 별도 RTF 중앙값끼리 계산한 비율과 다를 수 있다.

M1 KO 1.0×는 HTTP 전체 시간이 0.13% 늘어 개선을 입증하지 못했다. 다른 7조합은 약 1.05~5.95% 줄었다. 모든 조합이 같은 비율로 빨라졌다고 주장하지 않는다. 생성 RTF의 음성 길이는 기존 설정의 묶음 간 무음을 포함한다. HTTP 시간에는 인코딩·전송·수신 비용도 들어간다. 원시 첫 오디오 도착과 재생 버퍼 시뮬레이션을 기록했지만 실제 오디오 장치 검사나 끊김 보장은 아니다. [원시 HTTP 비교](../../results/round12_paired_http.json)

이전 11차의 독립 측정 배치와 이번 값을 나눠 개선율을 만들지 않았다. ARM 재측정과 1코어·1GB 서버 측정은 이번에 수행하지 않았다.

## 출력·호출·취소 검증

`experiments/check_portable_cache.py`에서 **M1/F1/M5/F5 × KO/EN 장문 × 0.70/1.25/1.30/1.50/2.0× = 40쌍**의 float32 파형이 모두 같았다. 두 모델의 각 생성이 실제 vector 8회였음도 세었다. [장문·소수점 배속 결과](../../results/round12_cache_regression.json)

`experiments/check_streaming_runtime.py`로 새 패키지를 서버에 로드했다. M1/F1 × 1.0/2.0×의 각 3묶음에서 전체 WAV·PCM 스트리밍 모두 24회 호출했고, 4쌍 PCM16이 같았다. ONNX 호출 스레드는 `tts_0` 하나였고 intra/inter 설정은 1/1이었다. 취소된 긴 요청은 전체 216회 예정 중 8회에서 중단됐으며 다음 요청은 200으로 정상 처리됐다. 회복 약 0.100초는 시험 당시 관측값이다. [실제 런타임 결과](../../results/round12_streaming_runtime.json)

`tests_condition_cache.py` 3개 검사도 통과했다. 복사·하드 링크 시 원본 파일 보존, manifest 설정 유지, 변환 실패 시 정리, 기존·중첩 출력과 중복 캐시 거부를 검사한다.

## 다음 실험의 근거와 한계

표준 경로를 먼저 프로파일링했다. vector 노드 실행 시간의 상위 항목은 DynamicQuantizeMatMul 약 29.4%, LayerNormalization 약 28.3%, Gelu 약 16.7%였다. 이는 워밍업·측정을 포함한 프로파일 진단이며 비프로파일 성능 개선율로 쓰지 않는다. 원시 대용량 추적은 Git에서 제외하고 집계만 보관했다. [연산별 비용](../../results/round12_mac_operator_costs.json)

이후에는 LayerNormalization·정확한 GELU·동적 정수 행렬곱의 중복이나 호출 비용을 조사할 수 있다. 10차에서 미채택한 타일·epilogue 후보를 새 근거 없이 다시 선택하지 않는다. 수학 근사나 모델 축소로 청취 품질을 바꾸는 작업은 이번 채택 범위에 없다.

새 WER/CER/MOS는 측정하지 않았다. 파형 일치는 기준 모델의 기존 품질 한계를 그대로 보존한다는 뜻이다. 사용자 피드백인 **1.5배속 일부 발음 뭉개짐은 아직 미해결**이며 단어 누락이라고 기록하지 않는다. 2.0 전용 retime을 중간 배속으로 확대하지 않았다.

## 사용·재현·인계

공개된 고정 revision의 retime 패키지를 다운로드한 후 [서버 준비 명령](../../docs/SERVER.md#표준-ort-조건-캐시-선택)을 실행한다. 새 학습 가중치가 없으므로 이번에는 HF에 중복 모델을 업로드하지 않았다. Git에는 준비 도구·측정 도구·작은 JSON 결과·기록만 추가한다. 원본 모델·음성·로그·프로파일·개인 키는 제외한다.

최적화 패키지로 로컬 청취 서버 7788을 실행해 상태 200·음색 10개·8스텝·한 추론 스레드를 확인했다. 실제 PCM 생성에서 1.25/1.30은 200, 1.251은 422였다.

재현 명령과 다음 과제는 [round12_state.json](round12_state.json)에 보관했다. 새 측정은 새 출력 파일을 지정한다. 메인에 성공한 최적화를 커밋·푸시하는 기존 사용자 지시를 따른다.
