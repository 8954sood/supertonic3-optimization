# 15차: 전체 정규화 확장과 그래프 크기 정보 보존

14차 main `a71156f`에서 시작했다. F1200 가중치·양자화·실제 denoising 8회·추론 한 스레드·기존 내부 배속 경로를 고정했다. 선택 패키지는 `models/round15-all-parts-row-norm`이며, 14차의 16행 C 커널을 그대로 사용한다. 새 학습·모델 축소·파형 후처리는 없다.

## 바꾼 계산

벡터 추정기 36곳만 바꾸던 행 병렬 정규화를 duration 처리기 10곳(폭 64), 텍스트 처리기 15곳(폭 256), 보코더 10곳(폭 512)까지 확장했다. 총 71곳이다. 독립된 16행을 함께 처리하고 잔여 행은 8→4→개별 행으로 처리한다. 각 행의 연산 순서와 FMA 위치는 유지한다.

`prepare_row_norm.py --all-parts`가 새 변환 경로다. 새 패키지를 한 번에 만들거나 기존 벡터 전용 패키지에 추가 적용할 수 있다. 변경되는 그래프는 ONNX shape inference를 먼저 수행해 크기·순위 정보를 저장한 뒤 정규화 노드를 바꾼다. 벡터 전용 기본 변환 동작은 유지했다. 초기값 텐서의 직렬화 바이트가 하나라도 바뀌면 변환을 거부하며, 수정 파일은 하드 링크를 끊고 저장한다. 기존 패키지를 덮어쓰지 않는다.

런타임은 manifest의 `row_norm_widths`에 따라 설치된 ORT와 폭 64/256/512의 수치 일치를 시작 시 검사한다. 이전 벡터 전용 패키지는 512만 검사하므로 호환성을 유지한다. 네이티브 소스와 기본 16행 빌드에는 이번 차수의 변경이 없다.

## 실패를 분리한 과정

1. 정규화 연산만 따로 비교했을 때 세 폭 × 여섯 행 길이의 18개 사례는 모두 바이트가 같았다(`round15_width_probe.json`).
2. 크기 정보를 보강하지 않고 세 부분의 35개 노드를 바꾼 첫 패키지는 전체 파형에서 최대 절대 오차 약 0.450289가 발생해 채택하지 않았다. 같은 기준 입력으로 분리하면 duration은 같고, 텍스트 처리기는 최대 약 1.79e-6, 보코더는 약 2.03e-6 달랐다. 텍스트의 미세 오차가 동적 INT8 추정기를 거치면서 확대될 수 있으므로 단순 허용 오차로 통과시키지 않았다.
3. ORT 최적화 후 그래프를 비교했다. 텍스트 처리기의 Transpose가 46→82, 보코더가 23→33으로 늘고 BiasGelu가 Gelu+Add로 분리됐다. 행렬곱 융합 경로도 달랐다. 크기 정보 부족이 주변 계산의 선택과 반올림에 영향을 준 것으로 판단했다. 진단 원본은 `round15_layout_failed.json`이다.
4. C의 출력 크기 추론 콜백도 시험했다. 이름 없는 미정 차원을 그대로 복사한 첫 시도는 여러 -1 차원 오류로 로드되지 않았다. 이를 건너뛰는 수정 콜백은 짧은 KO/EN 파형 검사에 통과했다. 다만 변환 전에 ONNX 크기 정보를 보존하면 기존 C 라이브러리만으로도 출력이 같아져, 콜백은 선택하지 않았다. 선택 C 소스의 SHA는 여전히 `ecbd921603741c3707be084c3547301abfb8981991859b96a280c598bf3d790c`이다.
5. 선택 그래프에서는 Transpose·MatMul·FusedMatMul·BiasGelu의 위 주요 개수와 경로가 기준으로 돌아왔다. 텍스트·duration의 일부 크기 관련 보조 노드는 여전히 다르므로 전체 비정규화 그래프가 같다고 주장하지 않는다. `round15_layout_selected.json`과 파형 검사를 함께 판단 근거로 삼았다.

최적화 그래프는 기기별 임시 진단 파일로만 만들고 삭제한다. 재현 도구는 `experiments/inspect_row_norm_layout.py`다. 미채택 C 콜백은 `round15_unused_shape_callback.patch`에 보존했다. 14차 C 소스 복사본에 `git apply --unidiff-zero`로 적용하면 `round15_shape_build.json`의 소스 SHA와 일치한다. 이 패치는 선택 엔진에 적용하지 않는다. C API 차원 복사·소유권 확인에는 [ORT 공식 소스](https://github.com/microsoft/onnxruntime/blob/main/onnxruntime/core/session/custom_ops.cc)를 참고했다.

실패한 단순 변환을 재현하려면 별도 실험 패키지에서 `convert_graph(source_graph, count, width, preserve_shapes=False)`로 duration/text/vocoder를 변환하면 된다. 이는 선택 실행법이 아니다. 실패 패키지와 초기 중복 패키지는 검증 후 정리하며, 원본·기준·선택 모델은 보존한다. 이번 두 임시 패키지에서 다른 파일과 공유하지 않던 약 284MB를 정리했다(`round15_cleanup.json`).

## 성능

Mac M4 Max, ORT 1.31.1 CPUExecutionProvider, intra/inter 1/1이다. 모델 로딩·호환 검사·파일 저장을 제외한 warm 측정이다. 같은 입력·음색·seed·속도를 사용하고 각 쌍의 실행 순서를 번갈아 바꿨다. 동시에 추론하지 않았다. 집계는 각 조합의 쌍별 감소율 중앙값을 동일 비중으로 다시 중앙값 낸 값이다.

- 직전 14차 대비: 짧은 KO/EN × M1/F1 × 1.0/1.5/2.0×, 12조합 × 6쌍에서 생성 시간 **4.73% 감소**. 12조합 모두 쌍별 감소율 중앙값이 양수였다.
- 실제 TCP/SSE: KO/EN × M1/F1 × 1.0/2.0×, 8조합 × 6쌍에서 전체 응답 **4.47%**, 추론 합계 **4.73%**, 첫 오디오 도착 **4.77% 감소**. 8조합 모두 전체 응답 시간의 쌍별 감소율 중앙값이 양수였다.
- 공개 uncached retime 표준 패키지와 별도 8조합 × 6쌍 비교: 생성 시간 **19.32% 감소**. 이전 실험의 퍼센트를 더하지 않았다.

| 실제 HTTP 조합 | 14차 생성 RTF 중앙값 | 15차 생성 RTF 중앙값 | 쌍별 HTTP 시간 감소율 중앙값 |
| --- | ---: | ---: | ---: |
| M1 KO 1.0× | 0.02791 | 0.02685 | 4.52% |
| M1 KO 2.0× | 0.03833 | 0.03724 | 4.38% |
| M1 EN 1.0× | 0.02891 | 0.02725 | 5.35% |
| M1 EN 2.0× | 0.04002 | 0.03723 | 6.76% |
| F1 KO 1.0× | 0.02908 | 0.02844 | 4.42% |
| F1 KO 2.0× | 0.04025 | 0.03864 | 3.82% |
| F1 EN 1.0× | 0.02983 | 0.02833 | 5.47% |
| F1 EN 2.0× | 0.04005 | 0.03848 | 3.36% |

RTF는 서버가 보고한 추론 합계 ÷ 출력 길이이며 묶음 간 무음을 포함한다. HTTP 시간에는 인코딩·전송·수신도 포함한다. 별도 실행 집단의 RTF 중앙값 비율과 쌍별 감소율 중앙값은 다른 통계량이다. Mac 결과를 Oracle ARM 또는 EPYC로 환산하지 않는다.

첫 core 교대 측정의 후보 경로는 중간 이름 `models/round15-inferred-row-norm`이다. 최종 선택 패키지는 공개 표준 조건 캐시에서 새로 만들었으며 5개 ONNX 그래프 모두 측정 후보와 SHA가 같음을 확인했다(`round15_final_build.json`). HTTP·확대 파형·패키지 검사는 최종 경로로 수행했다.

## 출력과 서비스 검사

- M1/F1/M5/F5 × KO/EN 짧은 문장·장문 × 0.70/1.00/1.25/1.30/1.50/2.00×의 96쌍에서 float32 바이트가 기준과 같았다. 각 생성의 실제 vector 호출도 8회였다.
- 단위 검사 22개: 정규화·준비 7개, 서버 13개, 원본 런타임 비교 2개. 세 폭 × 23개 행 길이 × 두 epsilon × 다섯 입력 분포의 수치 사례 690개를 바이트 비교했다.
- 실제 HTTP 검사에서 전체 파일과 스트리밍의 PCM이 같았다. 세 묶음은 24회 호출했다. 연결 취소는 전체 216회 중 8회 호출 후 멈추고, admission 반환과 후속 요청 정상 처리를 확인했다. ONNX 호출 worker는 `tts_0` 하나, intra/inter도 1/1이었다.
- 실행 패키지를 임시 추출하고 C 소스에서 빌드해 실제 1.25배속 음성을 생성했다. 기준과 파형 SHA가 같고 네이티브 바이너리를 포함하지 않았다. 약 169MB의 임시 압축 파일과 추출 폴더는 검사 후 삭제했다.
- 로컬 청취 서버를 선택 패키지로 재시작했다. 1.25/1.30 요청은 200, 소수 셋째 자리 1.251은 422이며 화면이 정상 응답했다. 이 시작 검사는 성능 측정으로 사용하지 않는다.

ASR·WER·CER·MOS는 이번에 새로 측정하지 않았다. 출력이 같은 검사 범위에서 기존 음성과 발음 특성도 보존되며, 기존 F1200의 품질 한계나 1.5배속 뭉개짐을 개선했다는 뜻은 아니다. HF의 학습 가중치를 변경하거나 새로 업로드할 필요가 없는 그래프·엔진 개선이다.

## 재현과 다음 작업

설정·SHA·전체 명령은 `round15_state.json`, 원시는 `results/round15_*.json`이다. 공개 모델 다운로드 → 표준 조건 캐시 → `prepare_row_norm.py --all-parts` 순서로 재현한다. 같은 source/output 경로를 쓰지 않는다. Linux ARM64 빌드 경로는 있으나 실기기 성능 검증은 아직 없다.

다음에는 선택 그래프를 새로 프로파일링한 뒤 벡터 추정기의 GELU와 전치 비용을 조사한다. 앞선 14차 프로파일에서는 정수 행렬곱 약 37%, GELU 약 20%였지만, 이번 선택 이후의 비율로 그대로 사용하면 안 된다. 다음 후보도 출력 바이트·실제 8회·한 스레드를 먼저 확인하고 순서 교대 측정에서 이득이 있을 때만 선택한다.
